6부 · C28

변경의 영향과 증거를 함께 갱신한다

지도에서의 위치는 이 장의 쉽게 말하면 상자에서 설명한다.

처리량만 보지 않고 연결 식별·버퍼 수명·순서·오류·종료와 문서의 사용 계약까지 추적한다.

심화큰 그림에서의 위치: P02 운영과 문제 해결

쉽게 말하면 라이브러리 코드를 고칠 때 영향을 받는 곳(세션 정합성, 버퍼 수명, 종료 순서)과 함께 갱신해야 할 테스트·문서를 정리한 점검표다.

처음 읽는다면 라이브러리에 기여하거나 내부를 수정하기 전에 읽는다.

수정 전에 네 가지 질문에 답한다

변경 경계의 포맷·빌드·테스트·실제 동작과 책의 출처를 함께 점검한다. 실행하지 않은 검증은 미실행으로 남긴다.

누가 데이터를 소유하는가, 어느 스레드가 상태를 바꾸는가, 어떤 연결의 작업인가, 무엇을 완료라고 부르는가를 확인한다. span을 소유 payload로 착각하거나 index만 저장한 지연 작업, 게시 성공을 상대 처리 완료로 취급하는 변경은 정상 한 번의 Echo만으로 찾기 어렵다.

기존 작업 트리와 사용자 변경을 먼저 확인한다. 관련 없는 변경을 포맷하거나 커밋하지 않는다. 라이브러리 공개 API가 바뀌면 예제·README·C# wire·패키지 소비자와 이 책을 함께 확인한다. 외부 코드는 명시적인 필요가 없으면 수정하지 않는다. 빌드 결과와 IDE 설정은 커밋하지 않는다.

표는 테스트 선택의 출발점이다. 하나의 테스트가 관련된 모든 안전 조건을 완전하게 증명한다고 주장하지 않는다. 가짜 CQ와 실제 kernel, GUI와 headless, 짧은 실행과 장기 안정성의 경계를 유지한다. 현재 코드의 위험과 과거 해결 이력은 A04의 원문 기록도 함께 본다.

정상 입력 밖의 경로를 같은 비중으로 본다

부분 송신, 원격 종료, 큐 포화, 게시 실패와 강제 종료를 포함한다. 최적화로 lock을 줄이면 validation과 쓰기·close 전이 사이에 세션이 재사용될 수 있는지 확인한다. 완료 컨텍스트를 재활용하면 이전 요청이 끝나기 전에 덮어쓰지 않는지 확인한다. memory 등록 전략을 바꾸면 실제 view·ID·offset 범위와 해제 순서를 다시 검증한다.

운영 조건의 경계도 기록한다. ValidateServerConfig의 enum cast 검사 누락과 adapter의 세대 정렬 비교처럼 현재 발견한 한계는 본문과 출처에 남긴다. 책을 쓰기 위해 제품 알고리즘을 몰래 바꾸거나 검사를 통과시키려고 주석·공개 심볼을 삭제하지 않는다. 별도 코드 수정은 영향과 회귀를 명시한 작업으로 분리한다.

책의 원고·출처·모델을 같은 변경으로 갱신한다

함수·테스트·설정이 바뀌면 evidence의 선택자와 검토 해시가 stale로 실패한다. 생성기가 새 코드를 포함하는 것과 설명을 다시 검토한 것은 다르다. 실제 소스와 본문·실험을 대조한 뒤 검토 기록을 명시적으로 갱신한다. 줄 번호만 고정하지 않으며 시작·끝 선택자가 0개 또는 여러 개면 먼저 범위를 고친다.

API 추가는 공개 헤더의 @api와 선언 대조, generated/api.json 갱신, A01의 주요 멤버 계약과 관련 장을 포함한다. 모델의 정상·경계·실패 테스트와 브라우저의 URL·저장·키보드·오프라인·인쇄 검사를 실행한다. 기존 이관 목록의 원문 변경이 있으면 새 내용을 먼저 대조하고 삭제 여부를 결정한다.

리뷰에서 변경 결과와 남은 위험을 설명한다

어떤 입력에서 무엇이 달라졌는지 먼저 적고, 소유권·순서·범위·종료에 대한 근거를 붙인다. 검증 명령, 실제 결과와 미실행 항목을 구체적으로 남긴다. C++ 변경은 저장소 스타일의 clang-format과 두 구성 빌드 기준을 따른다. 전체 테스트를 실행하지 않았다면 관련 필터만 통과한 사실을 구분한다.

최종 push 뒤에는 로컬 HEAD와 원격 main SHA, 작업 트리 상태를 확인한다. 원격 화면이 다르다는 이유만으로 force-push하거나 이력을 다시 쓰지 않는다. 같은 SHA라면 정확한 경로·branch와 표시 문제를 확인한다. main 반영과 새 바이너리 release·운영 채택도 다른 단계다.

핵심 세 줄과 다음 장

  1. 바꿀 계층과 영향받는 수명·순서를 먼저 정한다.
  2. 코드·예제·책·출처·검증 범위를 함께 갱신한다.
  3. 원격 SHA와 작업 트리·미실행 범위를 확인해 전달한다.

관련 부품은 장 머리의 지도에서, 다음 읽기는 선택한 경로에서 확인한다.
