같은 소스로 패키지를 만들고 ZIP만으로 소비한다

지도에서의 위치는 이 장의 쉽게 말하면 상자에서 설명한다.

문서 검사, 바이너리 빌드, 배포 후보와 정식 release 승인은 각각 확인할 조건이 다르다.

심화큰 그림에서의 위치: P02 운영과 문제 해결

쉽게 말하면 라이브러리를 ZIP 패키지로 만들어 다른 프로젝트에서 쓰는 절차와, 정식 배포에 필요한 조건을 다룬다.

처음 읽는다면 다른 프로젝트에 라이브러리를 넣어야 할 때 x64·구성·CRT·도구 체인을 맞춘다 절부터 읽는다.

x64·구성·CRT·도구 체인을 맞춘다

RIONetLite는 정적 C++ 라이브러리다. 0.x preview는 API·ABI 호환을 영구 보장하지 않는다. 소비자는 패키지 manifest의 compiler·Windows SDK·x64·Release·/MD 조건을 맞춘다. Debug /MDd 프로그램에 Release 라이브러리를 임의로 섞거나 헤더만 다른 버전으로 바꾸지 않는다.

공개 헤더는 include/rionetlite, 라이브러리와 PDB는 lib에 들어간다. Ws2_32·Mswsock·Mincore 링크 조건은 소비자 프로젝트가 보여 준다. 패키지는 기본적으로 UseMimalloc=false이며 최종 실행 파일의 allocator 선택과 분리한다. 저장소 내부 include/lib 경로가 소비자 빌드에 섞이면 “ZIP만으로 빌드했다”는 검사가 아니다.

현재 source snapshot을 고정한다

package.ps1은 Git의 관리 파일과 ignore되지 않은 새 파일을 inventory로 모아 경로·SHA-256과 전체 tree hash를 계산한다. 각 파일을 staging source에 복사하고 다시 해시를 검사한다. 복사와 패키징 중 작업 트리가 바뀌면 후보가 낡았다고 실패한다. 바이너리만 골라 놓고 어느 소스였는지 추측하지 않는다.

manifest에는 SourceCommit, SourceTreeSHA256, SourceDirty, SourceStatus, tag·도구 체인·해결된 SDK와 컴파일러 버전을 남긴다. dirty snapshot도 개발 후보를 만들 수 있지만 깨끗한 release commit과 동일한 승인으로 표시하지 않는다. dump·IDE cache·빌드 산출물은 Git과 snapshot의 입력에 넣지 않는다.

staging 소스로 새 라이브러리를 만든다

도구는 저장소의 이전 lib를 복사하지 않고 staging source의 프로젝트를 Release로 새로 빌드한다. 배포 후보는 /MD, /O2, non-/GL과 UseMimalloc=false를 사용하며 실제 SDK 버전을 확인한다. 공통 빌드의 Release 설정과 후보의 non-/GL 조건은 같은 것이라고 뭉뚱그리지 않는다.

헤더·lib·PDB·라이선스·보안/외부 고지·변경 기록과 소비자 예제를 묶는다. 오프라인 가이드는 source/docs/interactive_book/index.html에 포함된 source snapshot에서 읽을 수 있다. 패키지의 짧은 README는 그 가이드로 안내한다. 책을 별도 네트워크 사이트에서 가져오는 단계가 필요하지 않다.

버전 검사와 후보 생성을 재현한다

tools\verify-version.ps1 -ExpectedVersion 0.3.0
tools\package.ps1

version.h, vcpkg.json과 CHANGELOG의 버전이 일치해야 한다. 일반 package 명령은 개발 후보이며 현재 HEAD에 release tag가 있다고 가정하지 않는다. 결과 ZIP, ZIP SHA-256, source hash와 verification.json은 artifacts 아래에 남긴다.

도구는 완성한 ZIP을 새 검증 경로에 풀고 그 안의 PackageConsumer를 다시 빌드한다. 저장소·vcpkg의 우회 include/lib 경로를 끄고 실제 RIO Start/Stop 실행의 종료 코드 0을 요구한다. staging 폴더에서만 빌드한 결과보다 실제 배포 묶음의 누락을 찾기 좋은 검사다.

정식 release는 별도의 깨끗한 tag 조건을 요구한다

# 해당 release를 승인한 뒤의 명령이다. 이 책 작업이 tag를 만들지는 않는다.
tools\verify-version.ps1 -ExpectedVersion 0.3.0 -RequireReleaseTag
tools\package.ps1 -RequireReleaseTag

RequireReleaseTag는 HEAD의 v버전 tag와 깨끗한 작업 트리를 확인한다. 버전 숫자를 맞추기 위해 임의 tag를 만들거나 기존 tag를 덮어쓰지 않는다. 책 집필과 main push는 새 바이너리 release를 승인하는 요청과 다르다. 이번 판의 실제 package 검사 여부·후보 상태는 A05에서 확인한다.

release 판정에는 두 구성의 빌드·테스트, 실제 Echo/Chat, 메모리·지속 안정성·고정 환경 성능, 소비자 설치와 대상 OS 검증을 각각 기록한다. 과거 체크 표시를 새 release에 복사하지 않는다. 실패·skip·미실행·제외와 제품 채택 승인을 별도로 남긴다.

RIONetLite binary package

This is a 0.3.x preview for Windows x64 TCP/IPv4 servers. The package supplies a fresh Release static library, PDB, public headers and the exact source snapshot used to build it. API and ABI can change during 0.x. IPv6, UDP, TLS, client transport APIs and CMake/vcpkg overlay packages are outside this distribution.

Install Visual Studio 2026 with Desktop development with C++, MSVC v145 and Windows SDK. Open Developer PowerShell, extract the ZIP into a new directory, then run from that directory:

msbuild samples\package_consumer\PackageConsumer.vcxproj /t:Rebuild /p:Configuration=Release /p:Platform=x64 /p:VcpkgEnabled=false /p:VcpkgEnableManifest=false /p:VcpkgApplocalDeps=false
samples\package_consumer\bin\PackageConsumer.exe
$LASTEXITCODE

Exit code 0 means RIO initialization, start and stop succeeded. This consumer immediately stops; it is a lifecycle smoke test. To run an actual listening EchoServer, follow source/docs/interactive_book/index.html#chapter=build-and-run and build the supplied source. No repository checkout or vcpkg installation is needed for the binary consumer.

For an existing project, select x64 Release, /std:c++latest, /utf-8, /MD, the compiler/SDK versions in package-manifest.json, include include/, and link lib/RIONetLite.lib with Ws2_32.lib, Mswsock.lib and Mincore.lib. Use <rionetlite/server.h>. Do not link this Release library into a /MDd Debug executable. Build a matching Debug library from source/ instead. The package disables /GL; matching the recorded compiler remains the supported configuration.

package-manifest.json records compiler, SDK, runtime, optimization, Git commit, dirty state and source tree SHA256. source-files.json maps each source path to its SHA256. SHA256SUMS.txt covers delivered files except itself; the sibling .zip.sha256 covers the final ZIP. A dirty snapshot is a development candidate, not a tagged release. Keep the .lib, PDB and source from the same package together.

The packaging script builds from the captured snapshot, extracts the final ZIP, and builds/runs the consumer with global vcpkg integration disabled. artifacts/package-verification/<version>/verification.json is the local verification sidecar. A different clean PC and the full target OS matrix require separate acceptance.

If startup fails, record Error.code, native_code, field and message. Port 32452 must be free. See source/docs/interactive_book/index.html#chapter=configuration and source/SECURITY.md for diagnosis and private vulnerability reporting. ZIP은 현재 소스로 다시 만든다

패키지는 오래된 bin의 lib를 복사하는 결과가 되어서는 안 된다. 현재 package 도구는 version header에서 버전을 읽고 Git 관리 대상과 비무시 신규 파일의 SHA-256 snapshot을 만든다. 복사 전후와 build 후 원본 hash를 비교해 중간 source 변경을 거절한다.

snapshot 안의 소스로 Release x64 static library를 새로 빌드한다. compiler, SDK, runtime /MD, 표준, UTF-8과 최적화 조건을 manifest에 기록한다. 배포 lib는 whole-program optimization을 꺼 다른 consumer와의 도구 체인 결합을 줄인다.

완성 ZIP을 다시 풀어 repository와 vcpkg 경로 없이 package consumer를 빌드하고 RIO create/start/stop을 실행한다. stage folder가 성공했다는 것과 최종 ZIP 내용이 성공했다는 것은 다르다. SHA256SUMS와 ZIP hash도 함께 남긴다.

개발 snapshot package와 공식 release를 구분한다. RequireReleaseTag는 header 버전과 release tag, clean source의 관계를 검사한다. 현재 0.3.0 preview 소스에 v0.3.0 tag를 자동으로 만든다고 가정하지 않는다. 외부 새 PC 검증도 로컬 ZIP consumer와 별개의 gate다.

결과는 실행별 artifacts에 보관한다. dirty source snapshot은 개발 후보다. 위 로컬 검사를 운영 승인이나 모든 OS 인증으로 소개하지 않는다. 최종 package에는 source tree/file/ZIP SHA256을 기록한다.

최종 release commit의 버전과 tag는 tools\verify-version.ps1 -ExpectedVersion 0.3.0 -RequireReleaseTag로 검사한다. 개발 후보 packaging과 정식 release packaging은 구분하며, 정식 패키지는 tools\package.ps1 -RequireReleaseTag를 사용한다.
