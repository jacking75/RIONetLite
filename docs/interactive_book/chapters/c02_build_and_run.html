1부 · C02

두 구성으로 빌드하고 첫 연결을 확인한다

지도에서의 위치는 이 장의 쉽게 말하면 상자에서 설명한다.

컴파일, 테스트, listen, 바이트 왕복과 정상 종료를 순서대로 확인한다. 앞 단계의 성공이 뒤 단계를 대신하지 않는다.

입문큰 그림에서의 위치: P03 직접 실행해 본다

쉽게 말하면 개발 도구를 맞추고, 라이브러리·테스트·예제를 빌드하고, EchoServer를 띄워 실제 왕복이 되는지 확인하는 장이다. “빌드 성공”과 “서버가 응답한다”는 서로 다른 확인이다.

처음 읽는다면 같은 도구 체인과 저장소 루트에서 실행 절의 명령만 따라 하고, 오류가 나면 첫 오류의 계층 절을 본다.

서버 설정을 정한 뒤 포트에서 접속을 기다린다. 이때 소켓의 소유권은 라이브러리가 관리하고, 워커는 들어온 요청의 완료를 처리한다.

같은 도구 체인을 사용한다

프로젝트 기준은 Visual Studio 2026, MSVC v145, Windows SDK와 x64다. Visual Studio Installer에서 Desktop development with C++ 구성 요소를 설치한다. C# Chat 클라이언트까지 실행하려면 .NET 10 Windows SDK가 필요하다. C++은 /std:c++latest와 /utf-8을 사용하며 Debug와 Release를 모두 유지한다.

정책상 대상 OS는 Windows 10 1803 이상, Windows 11과 Windows Server 2019 이상이다. 이 범위의 모든 OS·Winsock provider 조합을 이번 판에서 실행했다는 뜻은 아니다. RIO 함수 표를 얻을 수 없거나 주소 매핑 API가 없는 환경에서는 명확한 초기화 오류로 처리한다. 다른 transport로 자동 대체하는 기능은 없다.

GoogleTest와 mimalloc은 루트 vcpkg.json의 manifest로 관리한다. vcpkg의 MSBuild 통합을 준비하고 최초 복원 로그를 확인한다. 최초 설치·복원에는 네트워크와 시간이 필요하다. 반면 생성된 책을 읽는 데는 네트워크가 필요하지 않다. 의존성 바이너리를 임의로 저장소에 복사해 복원 오류를 숨기지 않는다.

저장소 루트에서 실행한다

tools\build.ps1 -Configuration Debug -Rebuild
tools\build.ps1 -Configuration Release -Rebuild

스크립트는 VS 18.x 설치에서 MSBuild를 찾고 루트 솔루션을 x64로 빌드한다. -Rebuild는 재빌드 대상이며 -SkipTests를 주지 않으면 해당 구성의 두 테스트 실행 파일을 이어서 실행한다. 빌드 결과의 경고·오류 수와 테스트의 passed·failed·skipped를 따로 확인한다.

Debug의 CRT allocation hook 검사는 Release에서 적용 범위가 달라 skip될 수 있다. 이를 성공한 테스트 수에 합치지 않는다. 현재 판의 결과 수치는 실행 기록에서 구성별로 구분한다. Visual Studio에서 솔루션만 빌드한 결과와 테스트까지 실행한 결과도 구분한다.

listen 다음에 실제 응답을 확인한다

# 첫 터미널
bin\x64\Debug\EchoServer.exe --port 32452 --workers 2 --max-sessions 8

# 다른 터미널, 같은 저장소 루트
New-Item -ItemType Directory -Force .artifacts/logs | Out-Null
bin\x64\Debug\LoadClient.exe --port 32452 --connections 4 --duration 10 --scenario echo --json .artifacts/logs/first-echo.json
$LASTEXITCODE

listen 안내가 나와도 애플리케이션 프로토콜이 맞는지는 아직 모른다. 클라이언트 종료 코드 0, 실제 연결 수, 수신 패킷 수와 오류 카운터를 확인한다. received_packets는 양수여야 하고 connection_failures, data_errors, dropped_packets, timeouts는 0이어야 한다. 이 짧은 검사는 기능 확인이며 높은 처리량의 운영 승인 검사가 아니다.

끝낼 때 서버 콘솔에서 quit 또는 Ctrl+C를 사용한다. Stop 실패가 없어야 하며 종료 코드도 확인한다. 실행 제한을 원하면 --duration을 양수로 지정한다. 자동 검사 도구의 시작 대기, 클라이언트 timeout, 서버 정상 종료 대기는 서로 다른 기한이다.

실행한 것과 아직 안 한 것을 남긴다

성공 기록에는 커밋, 구성, 컴파일러, OS, 명령과 결과를 함께 남긴다. 테스트가 skip되었거나 도구가 없었다면 그 사실을 적는다. 메모리 검사와 긴 부하 검사는 기본 빌드 성공에 포함되지 않는다. 머신 전역 설정을 바꾸는 Verifier·PageHeap은 범위를 확인하고 복구 명령까지 준비한 뒤 별도로 실행한다.

Getting started

RIONetLite 0.3.x is a preview static library for Windows x64 TCP/IPv4 servers. 0.x API/ABI stability is not guaranteed. Target systems are Windows 10 1803+, Windows 11 and Windows Server 2019+; this is not a completed OS certification matrix. IPv6, UDP, TLS and client transport APIs are outside scope.

Install Visual Studio 2026, Desktop development with C++, MSVC v145, Windows SDK, Git and manifest-mode vcpkg with MSBuild integration. Initial dependency restoration needs network access. Open Developer PowerShell at the repository root:

tools\build.ps1 -Configuration Debug -Rebuild
bin\x64\Debug\EchoServer.exe --port 32452

Require build exit 0 and passes in both test suites. Release skips the Debug allocation hook test. When the server prints its listening message, run in a second terminal:

bin\x64\Debug\LoadClient.exe --port 32452 --connections 4 --duration 10 --scenario echo --json result.json

Require exit 0, four connected clients, nonzero received packets and zero connection failures, data errors, dropped packets and timeouts. Stop the server with quit and Enter, or Ctrl+C; require exit 0 without stop failed.

Create binds and allocates resources; Start runs workers; Stop drains them. Keep handler/logger alive until after Server destruction. Callback spans are borrowed until return. Copy to owned bounded storage for later game work. OnData returns consumed bytes; incomplete frames return 0 and remain in the transport. TCP can split/combine messages. Send(kQueued) accepts copied bytes, without acknowledging peer processing. Do not retry indefinitely in a callback. Retain both SessionId index and generation. Send/RequestClose/Stop can race safely; movement/destruction requires quiescent application callers. Start/Stop from the same server's event/logger callbacks is rejected; signal a control thread instead.

The README consumer immediately starts and stops. The running EchoServer is samples/echo_server/main.cpp. Detailed API contracts, framing and Chat protocol currently have Korean explanations. This English core guide and binary package guide cover installation and key contracts. Full translated tutorials are not supplied yet.

ChatClient needs .NET 10 SDK: dotnet build samples/chat_client/csharp_test_client.csproj -c Release. Start ChatServer on 32453 and two clients in the same room. tools/test-chat.ps1 checks golden fixtures and real TCP interaction with 1/2/4 logic shards. GUI interaction and clean-PC installation are separate acceptance checks.

설치와 첫 왕복

1. Visual Studio Installer에서 Visual Studio 2026의 **Desktop development with C++**, MSVC v145, Windows SDK를 설치한다. ASan에는 C++ AddressSanitizer 구성 요소도 필요하다.

2. Git과 vcpkg를 준비하고 vcpkg의 MSBuild 통합을 설정한다. 루트 vcpkg.json의 manifest 복원은 GoogleTest와 mimalloc을 받는다. 최초 복원에는 네트워크와 추가 시간이 필요하다.

3. Developer PowerShell에서 저장소 루트로 이동한다.

git clone --branch main https://github.com/jacking75/RIONetLite.git
cd RIONetLite
tools\build.ps1 -Configuration Debug -Rebuild

빌드 종료 코드 0과 두 테스트 suite의 [ PASSED ]를 확인한다. Release에서는 Debug allocation hook 검사 한 개가 skip될 수 있다. skip을 pass 개수에 합치지 않는다. RIONetLite.sln의 Debug|x64로도 빌드할 수 있지만 테스트 실행은 위 스크립트로 확인한다.

첫 번째 터미널에서 실행한다.

bin\x64\Debug\EchoServer.exe --port 32452

EchoServer listening on port 32452. Type quit or press Ctrl+C to stop.이 나오면 두 번째 터미널도 루트에서 실행한다.

bin\x64\Debug\LoadClient.exe --port 32452 --connections 4 --duration 10 --scenario echo --json result.json
$LASTEXITCODE
Get-Content result.json

종료 코드 0, connected=4, received_packets>0, connection_failures/data_errors/dropped_packets/timeouts=0이면 실제 왕복에 성공한 것이다. 숫자는 실행마다 다르다. 서버에서 quit과 Enter 또는 Ctrl+C로 끝낸다. stop failed 없이 종료 코드가 0이어야 한다. 최초 설치·복원까지 5분 안에 끝난다는 보장은 없다.

포트 충돌은 Get-NetTCPConnection -LocalPort 32452 -State Listen으로 확인하고 두 프로그램을 같은 다른 포트로 실행한다. 문제 해결을 참고한다.

빌드 환경과 첫 실패를 해석한다

이 저장소는 Visual Studio 2026과 MSVC v145를 기준으로 한다. C++ 구성은 x64 Debug와 Release이며 /std:c++latest와 /utf-8을 유지한다. 예제 C# 클라이언트는 .NET 10 Windows Forms다. 실행 파일의 종류마다 필요한 도구 체인이 다르다.

루트 vcpkg manifest가 GoogleTest와 선택적 mimalloc 의존성을 관리한다. 기존 PC의 우연한 include 경로나 오래된 lib를 사용하면 다른 PC에서 재현되지 않는다. 대표 빌드는 tools/build.ps1로 진행하고 실제 실행된 구성과 toolset을 로그에 남긴다.

Debug와 Release가 모두 필요한 이유는 assertion, 최적화, allocator hook과 timing이 다르기 때문이다. Debug만 통과한 코드가 Release에서 같은 상태 순서를 갖는다고 가정하지 않는다. Release에서 Debug 전용 할당 테스트가 제외되는 것은 그 범위의 의도된 차이다.

실패는 컴파일, 링크, 시작과 동작으로 나눈다. 헤더 오류는 컴파일 단계이고 unresolved external은 링크 단계다. 포트 bind 실패나 RIO provider 문제는 실행 단계다. 실행은 되지만 패킷이 잘못되는 문제는 프로토콜이나 수명 검증이 필요하다.

빌드 환경과 첫 실패를 해석한다: 적용한다

먼저 저장소 루트 PowerShell에서 두 빌드를 실행한다. 빌드가 끝나면 해당 구성의 테스트 실행 파일을 직접 실행한 결과를 확인한다. 문제가 생겼을 때 다른 구성의 오래된 exe를 실행하면 수정 여부를 판단할 수 없다.

공개 헤더나 플랫폼 설정을 바꿨다면 루트 솔루션의 두 구성을 확인한다. 책의 짧은 예시를 프로젝트에 옮기는 실습도 동일한 UTF-8과 최신 C++ 표준을 사용해야 std::expected와 std::span 계약을 그대로 적용할 수 있다.

실습에서 관찰할 값

  • 빌드 로그의 configuration과 x64를 읽는다.
  • 에러 개수뿐 아니라 경고와 링크 입력을 확인한다.
  • 테스트의 skipped와 failed를 별도로 기록한다.

두 구성의 빌드와 테스트 실행

tools/build.ps1

VS2026 MSBuild를 vswhere로 찾고 루트 솔루션 x64 구성에 필요한 옵션을 전달한다. 기본으로 unit과 integration 실행 파일을 모두 실행한다.

Path/PATH 중복 환경을 정규화해 Windows 프로세스 생성의 key 충돌을 피한다. 사용자 인증 정보를 출력하는 동작은 없다.

SkipTests는 의도적으로 실행 검증을 생략하는 옵션이다. 결과 보고에서는 빌드만 수행한 경우와 test까지 수행한 경우를 구분한다.

이 파일에서 추적할 연결

  • Common.props의 표준/toolset을 본다.
  • bin/tests/x64 경로를 확인한다.
  • package의 fresh isolated build와 구분한다.
