부록 · A05

설명·모델·실행의 근거를 함께 관리한다

독자는 index.html 하나를 열면 된다. 유지관리자는 원고, 출처와 재현 명령을 함께 갱신한다.

독자에게는 독립 HTML 하나를 전달한다

docs/interactive_book/index.html을 복사해 Edge 또는 Chromium에서 연다. 인터넷·서버·계정 없이 본문·검색·그림·실험·코드 탐험을 사용할 수 있다. Python과 Node는 읽을 때 필요하지 않다. 브라우저 저장소가 차단되면 읽기 위치·체크·화면 선택을 다음 실행에 보존하지 못하지만 현재 창의 학습 기능은 작동한다.

주소의 chapter와 section은 공유 가능한 읽기 위치다. 처음 샘플의 p1~p10 주소도 대응 장으로 이동한다. 실험 JSON은 schemaVersion=1, 최대 32KiB, 동작 128개까지 재실행한다. 임의 C++ 실행이나 실제 로그 재생 기능이 아니다. 인쇄에서는 모든 장과 대표 상태·정적 설명을 보여 준다. 링크로 감춘 경고나 실험을 직접 눌러야만 얻는 필수 설명은 없다.

저작 환경과 재현 명령을 맞춘다

저장소 루트에서 Python 3.10 이상, Node.js 20 이상과 npm, Windows PowerShell 5.1 이상을 사용한다. 브라우저 검사는 설치된 Microsoft Edge를 사용한다. 제품 빌드는 C02의 Visual Studio 2026·MSVC v145·Windows SDK·vcpkg가 별도로 필요하다. npm ci는 lock 파일대로 개발 검사 도구만 설치한다.

npm.cmd --prefix tools/book ci
tools\generate-api-docs.ps1
python docs/interactive_book/build_book.py --require-complete
tools\check-docs.ps1
npm.cmd --prefix tools/book run test:content
npm.cmd --prefix tools/book run test:models
npm.cmd --prefix tools/book run test:browser
tools\book\update_config_fixture.ps1 -Check

생성은 API JSON을 먼저 만든 뒤 HTML을 조립한다. API의 -Check와 책의 --check는 파일을 바꾸지 않고 오래된 결과에 실패한다. --require-complete는 36개 원고의 기술·문장 검토, 20개 실험과 모든 이관 항목의 완료를 추가 요구한다. 일반 생성 성공만으로 실제 RIO나 운영 인수에 통과한 것으로 판단하지 않는다.

manifest.json은 순서·고정 slug·절·실험·출처 파일 allowlist를, evidence.json은 함수 구간·코드 해시·실제 GTest 선언과 검토 해시를 기록한다. glossary.json은 정의·검색 별칭·관련 장을, migration.json은 원본 개정본과 내용별 목적지를 기록한다. chapters의 HTML은 저작 소스이며 독립 문서로 배포하지 않는다.

장 번호는 링크 안정성을 위해 바꾸지 않는다. 0부의 입문 장은 C01 뒤에 P01~P03으로 끼워 넣었고 기존 C02~C28의 번호와 slug는 그대로 두었다. 모든 장은 manifest의 level(입문·중급·심화·참고)을 가져야 하며 목차의 난이도 표시로 쓰인다. C02~C28 첫머리의 “쉽게 말하면” 상자는 그 장이 P02의 연결 일생 중 어디에 해당하는지 연결한다. 장을 새로 추가하거나 장면이 바뀌면 이 상자와 P02의 지도를 함께 고친다.

코드 변경은 해시만 바꾸고 끝내지 않는다

  1. 해당 공개 계약·실제 함수·관련 테스트를 읽고 변경 의미와 실패 경로를 정한다.
  2. 원고의 상태 전이·예산·예제와 실험의 생략 조건을 함께 고친다. source selector의 시작·끝은 파일 안에서 각각 유일해야 한다.
  3. 관련 native 검사와 순수 모델 사례를 실행한다. 테스트 이름 존재는 실행 통과와 구분한다.
  4. 검토를 마친 출처에 한해 reviewedSourceSha256과 reviewedTestSha256을 명시적으로 갱신한다. 생성기가 바뀐 해시를 자동 승인하지 않는다.
  5. API JSON·책을 다시 생성하고 내용·모델·오프라인 브라우저·문서 링크를 검사한다. 공유할 HTML이 새 코드 snapshot을 포함하는지 확인한다.

코드 탐험의 기준 commit은 {{COMMIT}}이며 파일별 SHA-256이 정확한 snapshot을 식별한다. 기준 commit 뒤 이 책 작업으로 바뀐 문서 도구는 해당 파일 해시를 함께 본다. 줄 끝도 raw byte 해시에 포함되므로 .gitattributes는 포함 소스의 LF/CRLF 정책을 명시한다. 기존 build.ps1의 혼합 줄 끝은 CRLF로 맞추고 원래 raw SHA와 LF 정규화 비교 SHA를 별도로 보존했다. 실행문 내용은 바꾸지 않았다. 과거 원문과 최신 소스가 달라졌으면 근거와 차이를 기록하고 최신 hash로 과거 실행 사실까지 바꾸지 않는다.

각 모델은 createInitialState·transition·validateState·view·serialize·parse를 갖는 순수 JavaScript다. 전이는 원본 state를 바꾸지 않고, 입력 범위·알 수 없는 동작·스키마를 거절한다. 모델의 표와 SVG는 같은 state에서 생성한다. 가상 시간·가상 성능은 실제 kernel/provider의 스케줄링과 구분한다.

기존 문서의 내용 단위를 추적한다

원래 Markdown 24개와 이후 main의 독자 문서·기술서·공유 TSV를 포함해 34개 개정본, 493개 내용 항목을 조사했다. 같은 경로의 원본과 작업 시작 당시 개정본은 별도 기록이다. 원문을 보존할 곳과 현재 설명을 대조할 곳을 각각 기록하고 SHA-256을 확인한 뒤 기존 독자 문서를 제거했다. 원래 삭제되어 있던 문서를 복구해서 다시 지우지 않았다.

옛 기술서의 250개 소스 쪽은 파일별 원본 해시·행 범위와 현재 탐험기를 대조하고 고유한 독해 포인트를 보존했다. 과거 UI 버튼과 목차·페이지 번호는 현행 탐색·20개 실험으로 대체했다. 당시 그림은 보조 자료로 보존하며 새 실험의 동작을 대신하지 않는다. TSV는 C++와 C#가 함께 검증하는 기계 입력이므로 원래 위치에 남겼다.

이번 판에서 실행한 범위를 확인한다

실제 RIO 검사는 집필 환경의 로컬 Windows에서 실행했다. ASan·Application Verifier·PageHeap·600초 안정성·긴 부하·고부하 검사는 이번 판에서 다시 실행하지 않았다. WinForms GUI의 사람 조작, 별도 PC 설치, 다른 Windows/provider 조합, 고정 장비 성능 baseline 승인과 실제 게임 운영 인수도 수행하지 않았다. 과거 실행 기록은 A04에 별도로 보존한다.

브라우저 자동 검사는 입력·이동·저장·오프라인·화면 폭·인쇄 구조와 대표 화면을 확인한다. 일반 독자가 학습 목표를 달성했다는 사용자 연구를 대신하지 않는다. ZIP consumer의 로컬 실행은 배포 후보 검사이며 release tag·외부 게시·운영 승인과 구분한다.

집필 단계를 완료한 결과를 남긴다

B00은 현재 코드·24개 원본·기술서의 내용 조사를, B01은 장·출처·모델·재현 가능한 개발 기반을 만들었다. B02는 독립 읽기 화면·검색·이력·테마·코드 탐험·접근성과 저장을 구현했다. B03은 Echo·프레이밍·부분 송신을 먼저 집필해 실제 검사와 연결했다.

B04~B07은 구조·메모리·수신·송신·종료·게임 큐·Chat·설정·진단·검사를 실제 구현과 대조해 집필했다. B08은 측정·튜닝·패키징·변경 안내와 다섯 부록 및 과거 기록을 완성했다. B09는 API JSON·문서 검사·README를 새 경로로 전환했고 B10은 내용별 대조와 해시 확인 후 기존 독자 문서를 정리했다.

B11은 33개 장·20개 모델의 내용·브라우저·인쇄와 실행 안내를 검사했다. B12는 최종 HTML·유지관리 방법·이관 결과를 이 부록과 JSON으로 옮기고 작업 계획을 제거했다. 완료 사실은 해당 검사 receipt와 범위를 함께 읽으며, 실행하지 않은 환경을 완료로 바꾸지 않는다.
