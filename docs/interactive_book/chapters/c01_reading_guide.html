패킷에서 게임 서버까지

첫 바이트 왕복을 실행하고, 비동기 요청의 수명을 읽고, 게임 로직을 안전하게 연결하는 책이다. 필요한 장부터 읽고 상태를 직접 바꾸어 본다.

이번에 해결할 질문으로 시작한다

서버를 먼저 실행한다

빌드, 공개 API, Echo 왕복부터 시작한다. 패킷 경계를 이해한 뒤 게임 로직 큐와 Chat으로 확장한다.

C02~C04 → C13 → C18~C20

내부 동작을 이해한다

RIO 요청과 등록 메모리에서 출발해 연결·수신·송신·종료를 따라간다. 상태와 카운터가 달라지는 이유를 읽는다.

C05~C17

문제를 찾아 수정한다

설정·지표·오류·테스트로 원인을 좁힌다. 측정 결과의 한계와 변경 영향도 함께 확인한다.

C21~C28

읽는 순서는 잠금 조건이 아니다. 관련 장 링크를 따라갔다가 브라우저의 뒤로 가기로 돌아올 수 있다. 실험 상태는 같은 창에서 장을 오가도 유지된다. “이전 단계”는 초기값과 동작 기록을 다시 실행해 그 상태를 만든다. 자기 점검 체크는 시험 점수가 아니라 독자가 남기는 읽기 기록이다.

C++과 TCP를 알면 출발할 수 있다

RAII, 이동과 복사, span, atomic과 mutex, TCP 바이트 스트림의 기본 개념을 아는 독자를 대상으로 한다. RIO의 요청 큐나 이 저장소의 내부 클래스는 처음 본다고 가정한다. 익숙하지 않은 용어는 A02에서 쉬운 설명과 코드 식별자를 함께 찾는다.

RIONetLite 0.3.x는 Windows x64 TCP/IPv4 서버용 preview다. TLS, 인증, 데이터베이스, 월드 시뮬레이션, UDP, IPv6 또는 클라이언트 transport API를 제공하지 않는다. Chat의 로그인은 예제 상태 전이이며 실제 계정 인증이 아니다. 인터넷 공개 서버를 만들 때 필요한 보안 경계는 애플리케이션이 설계해야 한다.

0.x에서는 API와 ABI가 바뀔 수 있다. 새로운 버전을 적용할 때 헤더만 바꾸거나 오래된 정적 라이브러리를 섞지 않는다. 서버 소유 객체, 메시지 수명, 빌드 구성을 함께 확인하는 C27의 소비자 검증을 따른다.

그림과 실제 실행은 다른 증거다

이 책의 20개 실험은 브라우저 안의 설명용 모델이다. Windows 네트워크 API를 호출하거나 실제 서버를 망가뜨리지 않는다. 예를 들어 완료 길이를 0으로 바꾸는 버튼은 안전 조건이 왜 필요한지 관찰하는 도구다. 그 버튼을 눌렀다고 현재 PC의 RIO provider에서 같은 오류를 발생시킨 것은 아니다.

실험에는 초기 조건, 허용 입력, 단계별 상태, 모델에서 생략한 동작과 실제 소스 연결을 붙였다. “실제 코드”는 생성 당시 작업 트리에서 포함한 원문이다. 줄 번호, 파일 SHA-256과 검토 기준 커밋을 표시한다. 별도 의사 코드는 의사 코드라고 적었다. 소스 탐험기에서 “관련 구간”, 등록된 “함수 전체”, “파일 전체”를 바꿀 수 있다.

검증의 층위도 분리한다. 문서 생성 검사는 경로와 해시를 확인한다. JS 검사는 설명 모델의 규칙을 확인한다. C++ 단위 테스트는 fake API와 순수 구조를 확인한다. 통합 테스트와 별도 Echo/Chat 실행은 실제 Winsock/RIO를 확인한다. 장시간 메모리·운영 부하 승인은 그 다음의 별도 증거다. 이번 판의 실제 실행과 제외 항목은 A05에 기록한다.

검색하고, 돌아오고, 내 실험을 남긴다

검색은 본문 문장, 공개 API와 용어 별칭을 찾는다. generation과 “세션 세대”, backpressure와 “배압”처럼 같은 개념의 다른 표기도 연결한다. 결과를 선택하면 관련 절이나 코드로 이동한다. 키보드에서 슬래시를 누르면 검색창으로 가고, Esc로 코드·실험 자료 창을 닫을 수 있다. 모바일에서는 상단 목차 버튼을 사용한다.

읽기 위치, 화면 테마와 자기 점검은 판본 정보와 함께 브라우저에 저장한다. 브라우저가 localStorage를 차단하면 저장할 수 없다는 안내를 표시하고 읽기와 실험은 계속 제공한다. 저장이 허용되어도 다른 PC나 브라우저로 자동 동기화되지는 않는다.

실험 JSON에는 초기 조건과 동작 목록이 들어 있다. 128동작·32,768자 상한과 스키마 검사를 거쳐 가져온다. 다른 PC에서는 이 HTML을 열고 JSON을 가져온다. file:// 주소에는 내 PC의 경로가 들어 있으므로 그 주소만 보내면 다른 사람도 같은 파일을 열 수 있다고 가정하지 않는다. 외부 코드나 HTML은 실행하지 않는다.

인쇄는 전체 본문, 펼친 심화 설명, 실험의 초기 대표 상태를 별도 DOM에 만든다. 현재 실패 상태의 조작 화면을 정상 상태처럼 인쇄하지 않으며 실제 창의 실험 상태도 잃지 않는다. PDF 저장은 브라우저의 인쇄 기능을 이용한다.

이 책을 사용하는 방법

C++ 문법을 조금 아는 서버 개발자가 첫 접속부터 RIO 수명 문제까지 이해하도록 구성했다. 네트워크 구현을 처음 보는 독자는 1부부터 순서대로 읽는다. 이미 서버를 운영하는 독자는 배압·세션·종료 장을 먼저 읽고 소스 독해편으로 이동한다.

화면 왼쪽 목차에서 장을 고르고 검색창에 Send, generation, 부분 송신 같은 단어를 넣는다. 검색은 이 파일의 전체 본문을 대상으로 한다. 검색 결과는 해당 쪽으로 이동한다. 그림의 재생은 개념 단계에 색을 붙이는 교육용 시각화이며 실제 실행 시간이나 처리량을 재현하지 않는다.

코드 블록은 두 종류다. 학습용 예시는 조건을 설명하는 짧은 조각이다. 실제 소스 독해편은 경로·줄 번호·파일 SHA-256을 붙인 현재 원문이다. 줄 번호는 이 책을 작성한 코드 스냅샷 기준이며 이후 수정으로 바뀔 수 있다.

실습을 시작하기 전에 로컬 Debug 빌드와 Release 빌드를 확인한다. 실패를 해결하면서 입력, 기대 결과, 실제 결과를 함께 기록한다. 빌드 통과, 단위 테스트 통과, 실제 RIO 통과와 운영 환경 채택은 각각 다른 증거다.

현재 라이브러리는 Windows x64 TCP/IPv4 서버다. TLS, 인증, DB, 월드 시뮬레이션이나 인터넷 보안 경계를 제공하지 않는다. Chat 로그인은 예제 상태 전이이며 사용자 신원 인증이 아니다. 기능 추가 제안은 구현된 기능과 분리해 설명한다.

원문을 읽는 순서

이제 API와 내부 구현을 직접 따라간다. 다음 쪽에는 현재 파일을 줄 번호로 분할해 수록했다. 한 함수가 여러 쪽에 걸치면 앞뒤 줄을 연결해 읽는다. 페이지 경계는 소스의 의미 경계가 아니므로 여는 괄호, 잠금 범위, 반환 위치를 함께 확인한다.

파일별 안내는 해당 구현에서 확인해야 할 구체적인 계약을 정리한다. 각 코드 쪽의 독해 포인트는 실제 원문에 나타나는 식별자에 맞춰 선택한다. 소스의 빈 줄과 주석도 유지해 오류 처리나 수명 설명을 임의로 제거하지 않는다.

먼저 config와 Server의 공개 계약을 읽고 src/server.cpp가 기존 transport로 넘기는 경로를 따라간다. 이후 session lifecycle, buffer RAII, accept, CQ worker, sender를 읽는다. queue adapter와 Chat은 transport와 게임 처리의 경계를 보여 준다. 마지막 테스트와 실행 도구는 실패를 어떻게 증거로 바꾸는지 보여 준다.

원문과 해설이 어긋나면 원문의 실제 분기와 단위 테스트를 먼저 확인한다. 이 책은 책 작성 당시의 구현을 설명하며, API 안정화나 성능 수치를 미래 버전에 보장하지 않는다. 경로에 impl 또는 detail이 들어 있는 헤더는 애플리케이션에서 직접 의존하지 않는다.
