연결 하나에 슬롯과 소유 워커를 배정한다

지도에서의 위치는 이 장의 쉽게 말하면 상자에서 설명한다.

accept가 성공한 뒤에도 RQ 생성, 소켓 설정, 콜백과 첫 수신이 남는다. 어느 단계에서 실패해도 슬롯을 한 번만 반환해야 한다.

중급큰 그림에서의 위치: P02 ② 연결

쉽게 말하면 연결이 들어올 때 accept 스레드가 하는 일을 따라간다. 미리 만든 세션 풀에서 빈 슬롯을 빌리고, 담당 I/O 워커를 정하고, OnConnected 뒤에 첫 수신을 게시한다. 중간에 실패하면 슬롯을 정확히 한 번만 돌려준다.

처음 읽는다면 세션 풀은 기동 시 준비하고 연결 때 빌린다와 연결 콜백을 끝내고 첫 수신을 게시한다를 먼저 읽는다.

세션 풀은 기동 시 준비하고 연결 때 빌린다

세션 풀을 미리 만드는 이유는 연결이 몰릴 때마다 등록 버퍼와 제어 구조를 새로 조립하지 않기 위해서다. 대신 최대 세션 수에 맞는 자원 예산을 시작 전에 지불한다. 종료한 슬롯도 참조·이벤트·통지를 마치기 전에는 빈 슬롯이 아니므로 현재 활성 연결 수가 상한보다 작아도 즉시 재사용할 수 없는 순간이 있다.

그림으로 보기 · 메모리·소유권·종료 순서를 실제 코드와 대조한다.

먼저 예측해 보기 · 세션 풀에 빈 슬롯이 없다. 새 연결을 어떻게 다루는가?

연결을 거절하고 받은 소켓을 정리한다 — accept는 WSAENOBUFS를 기록하고 백오프한다. L06에서 슬롯을 모두 사용해 본다.

SessionManager는 최대 세션 수에 맞춰 TcpSession과 수신·송신 등록 버퍼를 준비한다. 새 연결마다 큰 등록 메모리를 자유롭게 늘리는 구조가 아니다. 메모리 예산이 최대 세션 수에 선형으로 영향을 받는 이유다. accept된 소켓은 빈 세션 슬롯을 빌리고, 슬롯이 없으면 소켓을 닫아 연결을 거절한다.

풀의 Free·Leased·Quarantined와 연결 생명주기의 Free·Accepting·Active·Draining·Closing·Quarantined는 별도 상태다. 풀은 슬롯이 어디에 들어 있는지 관리하고 생명주기는 한 연결의 진행을 관리한다. 목록에서 꺼냈다는 사실만으로 네트워크 연결이 Active인 것은 아니다.

나머지 슬롯도 워커에 포함한다

세션 수를 워커 수로 나눈 몫에, 앞쪽 워커부터 나머지 한 개씩을 더한다. 5세션과 2워커라면 워커0은 [0,3), 워커1은 [3,5)를 맡는다. first_index는 앞 워커가 받은 나머지까지 반영한다. 단순 몫만 사용하면 마지막 슬롯이 어떤 워커에도 속하지 않을 수 있다.

초기 free list는 이 파티션을 교차로 섞는다. 5세션·2워커의 초기 대여 순서는 0,3,1,4,2다. 기동 직후 처음 접속들이 모두 워커0에 몰리지 않게 하는 선택이다. 연결이 실제로 할당된 뒤의 소유 워커는 세션에 저장되어 완료 큐 선택에 사용된다.

소켓을 세션에 옮기기 전에 실패를 처리한다

accept 스레드는 UniqueSocket으로 받은 소켓을 관리한다. 빈 슬롯이 없으면 그 소켓을 Reset하고 rejected 지표·로그를 남긴다. RQ는 수신·송신 각각 최대 미완료 요청 1개와 데이터 버퍼 1개로 생성하며, 세션의 소유 워커 CQ를 수신·송신 양쪽에 연결한다.

NewSession에서 RQ 생성이 실패하면 전용 accept 실패 사유로 슬롯을 정리한다. TcpSession::OnConnect는 주소 조회, TCP_NODELAY, 선택적인 keepalive 설정 뒤 소켓과 RQ를 소유하고 세대를 검사해 Active로 전이한다. setup 중간 실패를 성공 접속으로 통지하지 않는다. accept 실패 사유의 내부 정리는 공개 RequestClose와 다른 초기화 실패 경로다.

accept 시스템 호출 실패나 슬롯 고갈은 상한 있는 backoff를 적용해 바쁜 반복과 로그 폭주를 줄인다. RQ·소켓 setup의 실패 경로는 별도로 살펴야 하며 모든 실패가 같은 대기 정책을 거친다고 뭉뚱그리지 않는다. setup 로그의 operation과 native 오류를 보존한다.

연결 콜백을 끝내고 첫 수신을 게시한다

그림으로 보기 · accept부터 첫 수신까지의 보호 구간에서 먼저 상태를 바꾸어 본다. 아래 코드와 표는 이 그림의 조건을 세부로 읽는다.

먼저 결론 · accept 스레드가 listen 소켓에서 접속 하나를 받는다. Stop이 listen 소켓을 닫으면 대기를 깨우고 루프 조건을 다시 본다.

accept에서 첫 수신 게시까지의 순서는 이어지는 본문과 실제 코드에서 확인한다.

OnConnected를 호출한 뒤 세션이 여전히 연결 상태인지 확인하고 첫 수신을 게시한다. 그 마지막 접근까지 끝낸 뒤 connect callback pending을 해제한다. 종료 요청이 동시에 들어오면 소유 워커는 이 보호가 풀릴 때까지 닫힘 처리를 보류한다. 연결 콜백에서 만든 Player가 그 콜백이 반환하기도 전에 지워지는 순서를 막는다.

첫 수신 게시 실패도 정상 접속처럼 방치하지 않는다. initial_receive operation을 기록하고 해당 세대의 연결 종료로 연결한다. 콜백에서 종료를 요청한 경우에는 IsConnected 검사가 후속 게시를 막을 수 있다. 이 순서는 C07의 스레드 설명과 C12의 일반 수신 완료 경로를 연결한다.

반환과 재사용 사이에 격리가 있다

ReturnSession은 풀 lock 아래 Leased 슬롯인지 검사한다. TryRecycle이 성공하면 free list 뒤에 넣고, 미완료 참조가 있으면 quarantine 목록에 넣는다. 나중의 AllocClientSession이 격리된 슬롯을 다시 검사해 안전하게 반환된 것만 꺼낸다. 종료 통지를 했다는 사실만으로 즉시 새로운 연결을 덮어쓰지 않는다.

세션 풀은 transport 수명을 회수한다

SessionManager는 시작할 때 TcpSession 객체와 등록 버퍼를 만든다. Free list에서 슬롯을 빌려 accept에 주고 반환 시 TryRecycle 결과에 따라 Free나 Quarantined로 옮긴다. 아직 완료가 남은 슬롯은 바로 다음 연결에 할당하지 않는다.

세션 파티션은 index 범위를 worker에 나눈다. 세션 수가 worker 수로 나누어떨어지지 않아도 앞 partition에 나머지를 배정한다. free list는 worker 범위를 번갈아 넣어 첫 접속들이 worker 0에만 몰리지 않게 한다.

ForcedClose는 generation 조회와 SetDisableNetwork를 reserve/recycle과 같은 pool lock 안에서 수행한다. 조회 후 잠금을 놓고 close하면 그 사이 새 generation으로 재사용된 슬롯을 닫는 검사-사용 경쟁이 생길 수 있다.

transport recycle은 outstanding I/O와 close notification을 기준으로 한다. 게임 큐에서 해당 이벤트를 소비할 때까지 transport 슬롯을 항상 붙잡는 구조는 아니다. adapter의 gate와 Player의 id 비교가 애플리케이션 수명을 별도로 지킨다.

세션 10개와 worker 3개면 partition 크기는 4,3,3이다. interleaved free list의 초기 index가 실제로 서로 다른 owner worker를 가리키는지 확인한다. logic shard의 index modulo 배정은 이 transport partition과 같은 규칙이 아니다.

close 후 게임 이벤트가 늦게 처리되는 실습에서 새 Player를 이전 id로 erase하지 않는다. transport slot이 재사용되는 것은 정상이며 application은 이전 close와 현재 Player.id를 비교해야 한다.

  • generation 검사와 close 전이의 잠금 범위를 본다.

accept와 첫 수신 사이의 순서를 지킨다

Accepter는 별도 thread에서 blocking accept를 실행한다. Start는 listen socket의 raw handle 값을 thread 생성 전에 캡처한다. 다른 스레드의 Stop이 UniqueSocket을 Reset할 때 thread가 뒤늦게 wrapper를 읽는 경쟁을 피하려는 것이다.

새 소켓을 받으면 세션 슬롯을 예약하고 해당 owner의 CQ로 request queue를 만든다. 현재 RQ는 수신·송신 각각 최대 한 요청과 한 buffer를 사용한다. 주소, TCP_NODELAY와 선택 keepalive 설정이 성공해야 세션을 활성화한다.

OnConnected 동안 애플리케이션은 RequestClose를 호출할 수 있다. close worker가 이를 처리하더라도 accept thread가 첫 recv를 게시하고 마지막 세션 접근을 끝내기 전에 slot을 recycle하면 안 된다. connect_callback_pending flag는 callback 반환뿐 아니라 첫 recv 시도까지 보호한다.

accept 실패나 세션 풀 고갈이 계속되면 상한 있는 backoff를 적용한다. 무조건 빠른 재시도는 CPU와 로그를 소진한다. 이 거절은 공개 EventHandler에 별도 거절 callback을 추가한 계약이 아니라 logger와 metrics를 통해 관찰한다.

accept와 첫 수신 사이의 순서를 지킨다: 적용한다

OnConnected를 100ms 막고 다른 스레드에서 RequestClose를 시도하는 통합 테스트를 생각한다. OnClosed가 먼저 호출되면 애플리케이션은 존재하지 않는 Player의 close를 보거나 순서를 잃을 수 있다. 테스트는 callback 진입·해제 신호를 사용해 순서를 확인한다.

Stop은 listen socket을 닫아 blocked accept를 깨우고 thread를 join한다. callback이 영원히 기다리면 join도 끝나지 않으므로 deadline을 하드 중단 장치로 해석하지 않는다.

실습에서 관찰할 값

  • listen handle 캡처가 thread 생성보다 먼저인지 본다.
  • OnClosed가 OnConnected를 추월하지 않는지 본다.
  • accept 실패의 backoff와 native error를 확인한다.

생각하고 확인한다

connect flag를 callback 직후 내리면 왜 충분하지 않은가.

해설 펼치기

accept가 다음 줄에서 첫 수신을 게시하려고 세션을 다시 접근한다. flag가 먼저 내려가면 close worker가 slot을 recycle할 수 있어 그 접근이 새 세대의 버퍼나 소켓을 건드릴 수 있다. 마지막 접근 뒤에 flag를 내린다.

세션 개수가 worker로 나누어떨어지지 않는 일반 경우를 처리하는 작은 constexpr 함수다. base와 remainder를 나누고 앞 worker에 하나씩 추가한다.

accept와 초기 callback 보호

RIONetLite/impl/server_net_accepter.h

Accepter는 blocking accept thread를 소유한다. Start에서 listen raw handle을 먼저 캡처하고 Stop에서 wrapper를 Reset해 accept를 깨운다. wrapper 자체를 다른 thread에서 늦게 조회하지 않는다.

새 연결에는 pool slot과 해당 worker CQ의 RQ를 붙인다. OnConnected와 첫 recv를 모두 마친 뒤 connect pending flag를 내린다. close worker의 recycle과 마지막 accept 접근의 경쟁을 방어한다.

반복 accept 오류와 pool 고갈은 backoff한다. request queue와 socket 설정 실패는 native operation 로그로 보고하며 실패한 슬롯도 연결 예외 경로로 정리한다.

이 파일에서 추적할 연결

  • TcpSession의 connect flag와 lifecycle을 본다.
  • server_net.h DisConnect delegate의 pending 분기를 읽는다.
  • blocked connect integration의 event 순서를 확인한다.

세션 pool과 generation close gate

RIONetLite/impl/session_manager.h

세션 pool을 시작 시 만들고 worker partition마다 고정 TcpSession을 준비한다. free list는 worker 순서로 interleave해 cold-start 접속이 한 worker에만 몰리지 않게 한다.

ReturnSession은 Leased 상태의 중복 반환을 막고 outstanding가 남은 연결을 Quarantined로 둔다. 다음 allocation 때 recycle 가능한 quarantine을 다시 free로 옮긴다.

ForcedClose의 uid 조회와 disable 전이는 pool reserve/recycle과 같은 lock 안에 있다. 이 잠금 범위가 검사와 사용 사이 새 generation을 닫는 경쟁을 막는다.

이 파일에서 추적할 연결

  • SessionLifecycle의 reserve/recycle 조건을 본다.
  • sender 내부 generation 재검사를 읽는다.
  • Game Player.id와 transport pool 수명을 구분한다.
