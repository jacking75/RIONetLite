콜백의 빌린 범위를 소유하는 이벤트로 바꾼다

지도에서의 위치는 이 장의 쉽게 말하면 상자에서 설명한다.

게임 처리를 다른 스레드로 옮길 때 데이터 복사, 순서, 세대와 포화 정책을 함께 옮겨야 한다.

중급큰 그림에서의 위치: P02 게임 로직 워커

쉽게 말하면 OnData로 받은 바이트를 복사해 게임 로직 스레드로 넘기는 큐(QueuedEventAdapter)를 다룬다. 콜백은 짧게 끝내고 무거운 게임 처리는 별도 스레드가 세션 순서대로 처리한다. 큐가 가득 찼을 때의 정책도 함께 정해야 한다.

처음 읽는다면 payload를 복사한다, TryPop의 반환값, full이어도 close를 버리지 않는다 절을 읽는다.

OnData의 span 대신 payload를 복사한다

QueuedEventAdapter는 EventHandler 구현이다. 연결·raw data·닫힘 이벤트를 shard별 사전 확보 저장소에 넣고 session.index % shard_count로 목적지를 고른다. 각 slot은 header와 max_payload_bytes 크기의 payload를 소유한다. 콜백이 끝나 원래 링이 재사용돼도 소비자는 복사본을 읽는다.

이 큐가 갖는 것은 완성된 게임 패킷이 아니라 raw stream chunk다. OnData 범위가 max_payload_bytes보다 크면 여러 chunk로 나누어 복사한다. 하나의 TCP coalesce가 메시지 한도보다 크다고 바로 큰 패킷 오류로 오판하지 않는다. 게임 워커는 순서대로 받은 chunk를 자기 입력 버퍼에 붙여 길이 헤더를 해석한다.

생성자의 모든 차원은 양수이며 kDisconnect 정책에는 CloseRequest가 필요하다. 잘못된 구성은 std::invalid_argument를 던진다. Server::Create의 expected 오류 계약과 같은 것으로 설명하지 않는다. 앱은 adapter 생성 실패와 기동 시 메모리 확보 실패를 자기 초기화 경로에서 처리한다.

TryPop의 반환값을 모두 처리한다

먼저 결론 · payload 크기와 세션 인덱스를 먼저 검사한다. 인덱스로 담당 샤드를 고른 뒤 잠금 안에서 세대 게이트를 확인한다.

복사된 이벤트와 parked close를 소비한다의 순서는 이어지는 본문과 실제 코드에서 확인한다.

소비자는 재사용하는 destination 버퍼를 준비하고 TryPop을 반복한다. kEvent면 header.payload_bytes만큼의 복사본을 처리한다. kDestinationTooSmall이면 이벤트를 제거하지 않으므로 header의 크기 이상 버퍼를 준비한 뒤 같은 이벤트를 다시 읽는다. kEmpty는 현재 시점에 읽을 이벤트가 없다는 뜻이다. producer가 살아 있다면 전체 처리가 끝났다는 뜻은 아니다.

shard 접근에는 짧은 mutex가 있다. 이 API를 lock-free라고 설명하지 않는다. 한 shard의 게임 상태를 한 소비자가 소유하면 PlayerMap의 일반 처리를 별도 전역 잠금 없이 구성할 수 있지만, 여러 소비자를 붙이는 것으로 같은 Player의 순서까지 자동 보장되는 것은 아니다.

kRejectNewest를 “라이브러리가 원래 바이트를 보관했다가 공간이 생기면 다시 콜백한다”라고 설명하면 잘못이다. 큐가 비었을 때 원래 TCP span을 다시 호출할 wakeup이 없기 때문에 현재 정책은 의도적인 손실 정책이다. Chat은 kDisconnect를 사용한다.

full이어도 close를 버리지 않는다

먼저 예측해 보기 · 이벤트 링이 가득 찬 순간 close가 왔다. 어떻게 하는가?

세션 게이트에 보류해 선행 이벤트 뒤 전달한다 — parked close는 종료 유실을 막는다. L14에서 depth와 링 용량을 비교한다.

close를 data처럼 버리면 게임 로직의 Player가 연결 종료를 보지 못해 남을 수 있다. 링이 full이면 세션 gate에 close reason과 보류 시점을 저장하고 parked index를 기록한다. depth도 증가하므로 링 capacity보다 전체 event_queue_depth가 커질 수 있다.

TryPop은 그 세션의 in_ring이 0인 parked close를 먼저 합성해 전달한다. 따라서 앞 data가 남아 있으면 close를 앞질러 전달하지 않는다. 같은 index의 새 generation connect는 parked close를 전달하기 전까지 거절해 이전 close가 새 gate에 덮어써지지 않게 한다. 반면 close가 이미 링에 있는 경우에는 링의 순서가 이전 이벤트→close→새 connect를 보존한다. “모든 새 connect는 이전 close 소비 전까지 금지”라는 더 강한 규칙으로 일반화하지 않는다.

generation 비교에는 현재 값보다 작은 세대를 거절하는 조건도 있다. uint64 순환에서 0을 건너뛰는 SessionLifecycle 헬퍼 검사만으로 이 애플리케이션 gate의 모든 wrap 시나리오가 검증된 것은 아니다. 장기 ID 저장 정책을 바꿀 때는 이 비교도 함께 검토한다.

예산과 배출 조건을 함께 확인한다

shards×events_per_shard×max_payload_bytes는 payload 저장소의 주된 예산이다. session gate, parked index, slot header, mutex와 allocator 비용이 추가된다. EstimatedMemoryBytes는 이 저장소의 추정치이며 프로세스의 전체 commit·kernel·thread stack을 보장하지 않는다.

adapter.metrics의 depth·high watermark·rejections·dequeued·wait total/max를 본다. Server::Metrics의 event_queue 필드는 adapter를 자동으로 합치지 않으므로 별도 snapshot을 읽는다. 종료 시 링의 count만 보지 말고 parked close가 포함된 depth와 실행 중 작업도 배출한다.

QueuedEventAdapter는 raw chunk를 복사한다

QueuedEventAdapter는 EventHandler 구현이다. 네트워크 callback을 Connected, Data, Closed 이벤트로 바꾸고 session.index modulo shard_count로 소비자를 고른다. 각 shard는 고정 slot과 payload 저장소를 생성 시 확보한다. 생성 인수가 0이거나 disconnect 정책에 close 함수가 없으면 예외로 거절한다.

max_payload_bytes는 하나의 queue slot 용량이다. 네트워크가 그보다 큰 raw data를 넘기면 OnData가 여러 chunk로 나눠 복사한다. slot의 크기가 최대 패킷과 같아도 chunk가 패킷 경계를 의미하지 않는다. 게임 worker가 입력을 이어 붙이고 실제 헤더를 해석한다.

shard 접근에는 짧은 mutex를 사용한다. 큐가 꽉 찼을 때 공간을 기다리는 동작은 없지만 완전한 lock-free 구현은 아니다. “대기 없이 거절”이라는 포화 정책과 잠금 경쟁으로 잠시 기다릴 가능성을 구분한다.

EstimatedMemoryBytes는 slot, payload, gate와 parked index 등을 계산한 추정이다. allocator metadata와 실제 process의 모든 메모리를 포함하지 않는다. transport 등록 버퍼와 game 입력 벡터, broadcast inbox 예산도 따로 더한다.

QueuedEventAdapter는 raw chunk를 복사한다: 적용한다

heartbeat 256개는 총 2048바이트다. 이것이 한 수신 callback에 들어와도 1024바이트 slot 두 개로 나뉘어 처리되어야 한다. 큰 정상 input을 oversize packet으로 오해해 종료하는 오류를 피하는 것이 chunk split의 목적이다.

샤드 2개, 각 4 event, payload 1024로 작은 실습 큐를 만든다. 큰 input에 대한 event 순서와 정확한 byte concatenation을 비교한다. byte 수락과 logical packet 해석을 두 단계로 나눠 확인한다.

실습에서 관찰할 값

  • slot payload보다 큰 raw callback을 분할한다.
  • chunk를 이어 붙인 바이트가 원본과 같은지 본다.
  • mutex 구현을 lock-free라고 문서화하지 않는다.

생각하고 확인한다

parked close도 남은 작업이다

Connected와 Data를 받은 게임 worker는 Player를 만든다. OnClosed가 큐 포화 때문에 사라지면 Player가 영원히 남을 수 있다. adapter는 close가 링에 들어가지 못하면 SessionGate에 close_parked와 reason을 저장하고 shard의 parked index 목록에 올린다.

parked close는 해당 세션의 링 이벤트가 모두 소비된 뒤 TryPop이 합성해 전달한다. gate.in_ring이 0인지 확인하는 이유는 같은 세션의 Data를 추월하지 않기 위해서다. 다른 세션의 이벤트와 서버 전체의 전역 순서를 보장하는 방식은 아니다.

event_queue_depth는 일반 링 항목과 parked close를 모두 포함한다. depth만 보고 게임 종료를 결정할 때 parked close를 빼면 실제 남은 종료 이벤트가 있는데도 empty로 보인다. high watermark와 wait timing도 이 종료 항목을 포함해 관찰한다.

이전 generation의 parked close가 전달되기 전 같은 index의 새 Connected는 거절한다. transport의 slot recycle과 application event 소비는 별개이므로 gate가 오래된 close를 새 세대로 덮어쓰지 않도록 하는 방어다.

parked close도 남은 작업이다: 적용한다

capacity 1인 큐에 Connected를 넣고 Closed를 이어 넣는다. Closed는 parked가 된다. 첫 TryPop으로 Connected를 꺼내도 depth가 1이어야 한다. 다음 TryPop으로 Closed가 나오면 depth가 0이 된다.

  • 동일 세션 Data 뒤에 Closed가 나오는지 본다.
  • 새 generation이 parked close를 덮지 않는지 본다.

TryPop과 Player 소유권을 연결한다

Chat은 shard마다 한 game worker와 로컬 PlayerMap을 둔다. 해당 shard로 오는 event만 worker가 꺼내고 Player의 phase, room과 input을 바꾼다. 다른 worker가 같은 map을 직접 순회하거나 수정하지 않으므로 게임 객체의 소유권이 명확하다.

TryPop은 destination에 payload를 복사한다. destination이 작으면 kDestinationTooSmall을 반환하고 항목을 소비하지 않는다. 반복 호출에서도 같은 항목이 막히므로 header.payload_bytes에 맞는 저장소를 준비하거나 설정 오류를 처리한다.

Connected에서 Player.id 전체를 저장하고 Data와 Closed에서 index뿐 아니라 id equality를 확인한다. 오래된 close로 새 Player를 지우지 않는 핵심 분기다. sequence는 event 정렬과 진단에 도움이 되지만 generation을 대신하지 않는다.

worker는 payload를 Player.input에 이어 붙인 뒤 ConsumeInput을 반복한다. 완성된 packet만 지우고 미완성 꼬리를 보관한다. adapter가 transport input을 이미 소비했으므로 게임 입력 버퍼가 이 잔여 바이트의 유일한 소유자다.

유계 event 저장과 parked close

src/queued_event_adapter.cpp

고정 slot payload와 per-session gate를 생성 시 준비한다. shard mutex로 ring과 gate를 함께 보호하고 OnData는 callback의 borrowed span을 own slot으로 복사한다.

close는 ring이 full이어도 gate에 parked하여 보존한다. 해당 세션의 앞 event가 배출되면 TryPop이 close를 합성한다. depth는 두 저장 경로를 모두 포함한다.

RejectNewest는 raw byte를 소비해 버리는 손실 정책이고 Disconnect는 실패 chunk에서 close 요청을 실행한다. framed TCP와 최신 game command drop을 혼동하지 않는다.
