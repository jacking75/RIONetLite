부록 · A01

호출 전에 수명과 반환값을 확인한다

아래 목록은 공개 헤더의 최상위 심볼과 직접 작성한 멤버 계약을 함께 보여 준다. 구현 클래스의 편의 함수는 애플리케이션 API에 포함하지 않는다.

namespace와 소유권을 먼저 정한다

신규 코드는 include/rionetlite/와 rionetlite namespace를 사용한다. Server는 내부 구현을 단독 소유하는 move-only 객체이며 handler와 logger는 빌려 쓴다. 생성 순서를 handler·logger, Server 순으로 두어 파괴가 반대로 일어나게 한다. 이동·대입·파괴 전에 모든 애플리케이션 호출자가 빠져나와야 한다. 자기 콜백 안에서 Server를 파괴하지 않는다.

소멸자는 미종료 transport의 정리를 시도하지만 종료 오류를 반환할 수 없다. 정상 경로에서는 명시적으로 Stop을 호출해 결과를 검사한다. 소멸자가 실패를 없애거나 미완료 등록 메모리를 강제로 안전하게 해제해 주는 것으로 기대하지 않는다. 종료 timeout과 의도적 자원 보존 경로는 C17에서 확인한다.

기본형 값, span과 string_view의 수명은 다르다. SessionId는 값으로 보관한다. OnData의 span과 Logger의 string_view는 호출 중에만 유효하다. 다른 스레드로 넘길 데이터는 반환 전에 복사한다. Send의 입력 span은 반환 전에 복사되므로 호출 후 원본을 다시 사용할 수 있다.

함수와 콜백의 계약을 대조한다

이동한 원본 객체의 state는 kStopped, Metrics는 0이다. Send는 kClosing, RequestClose는 false이며 Stop과 Start는 kInvalidState 오류를 반환한다. 이동한 원본의 Stop을 일반적인 반복 종료 성공과 혼동하지 않는다. Start는 내부 시작 전에 kRunning을 게시하므로 시작 도중 조회와 콜백에서도 그 상태가 보인다.

Server의 동시 호출 허용은 애플리케이션의 공유 상태까지 자동 보호한다는 뜻이 아니다. Handler와 Logger의 자료구조는 사용자가 보호한다. Stop의 다중 호출은 동일 종료 결과를 기다리지만, 콜백에서 호출하면 재진입 오류다. 소유 스레드로 종료 요청을 전달한다.

오류 계층과 종료 원인을 구분한다

Error의 category는 실패한 계층, code는 공개 오류 종류다. native_code는 Winsock·Windows 원인을 보존하며 field는 설정 항목, message는 문맥이다. 성공 여부만 출력하면 bind 충돌과 RIO 미지원, 자원 부족을 구분하기 어렵다. Error의 string은 값이 소유하며 로그로 전달하는 view는 별도 수명 규칙을 따른다.

enum정의된 값사용 지점
ErrorCategorykNone, kConfiguration, kLifecycle, kWinsock, kRio, kResource, kInternal설정·플랫폼·수명·자원 실패의 계층이다.
ErrorCodekNone, kInvalidConfiguration, kAlreadyInitialized, kInvalidState, kWinsockStartupFailed, kListenSocketCreateFailed, kBindFailed, kListenFailed, kRioUnavailable, kRioCompletionQueueCreateFailed, kSessionPoolCreateFailed, kThreadStartFailed, kShutdownTimedOut, kResourceAllocationFailed, kInternalErrorCreate·Start·Stop 및 설정 검증의 실패를 기록한다.
CloseReasonkNone, kPeerClosed, kApplicationRequest, kProtocolError, kReceiveError, kSendError, kServerStopping, kOverloaded, kIdleTimeout, kInternalError연결 종료 통지의 원인이다. RequestClose로 모든 내부 원인을 지정할 수 있는 것은 아니다.
DecodeErrorkNone, kInvalidLength, kMessageTooLarge덜 도착한 정상 패킷은 오류가 아니며 소비하지 않고 기다린다.
PollEventResultkEvent, kEmpty, kDestinationTooSmalldestination 부족은 이벤트를 제거하지 않는다. 필요한 payload_bytes를 확인한다.

ToString은 ErrorCategory, ErrorCode, SendResult, CloseReason에 대한 overload를 제공한다. enum 정수값을 그대로 wire protocol로 사용하지 않는다. 알 수 없는 cast 값의 fallback은 오류 변환 구현에서 확인한다. C++ enum에 새 값이 추가되면 이 표와 변환 함수·검사를 함께 검토한다.

디코더는 미완성 꼬리를 소유하지 않는다

LengthPrefixedDecoder의 kHeaderBytes는 4다. max_packet_bytes는 헤더를 포함한 최대 길이다. 생성자는 noexcept이며 별도 입력 검증을 하지 않으므로 호출자가 최소 4 이상으로 지정한다. 길이 0~3은 kInvalidLength, 설정 최대 초과는 kMessageTooLarge다. 최대와 같은 길이는 허용한다.

Decode는 완성된 앞부분마다 handler를 부르고 consumed_bytes와 packet_count를 누적한다. 정상 패킷 다음 잘못된 길이가 있으면 앞부분의 소비량과 오류가 함께 반환된다. handler 예외는 Decode 밖으로 전파되며 함수가 호출자에게 결과를 반환하지 못한다. EventHandler 안에서 쓰는 경우 상위 콜백 격리와 protocol close 경로를 함께 고려한다.

불완전한 꼬리를 다음 입력과 합치는 책임은 호출자에게 있다. 네트워크 OnData에서는 실제 소비량만 반환해 receive 링이 보관하게 하고, Chat 로직에서는 복사한 조각을 Player 입력에 누적한다. 각 handler가 받은 패킷 span도 원본의 view다.

공개 헤더의 심볼 목록을 확인한다

이 표는 tools/generate-api-docs.ps1이 선언과 @api를 대조해 만든 JSON에서 생성한다. 멤버 함수·필드의 전체 설명을 자동 추론한 목록은 아니며 위 계약과 C21·C22의 설정·지표 설명을 함께 읽는다.

version.h의 RIONETLITE_VERSION_MAJOR, MINOR, PATCH와 문자열 버전은 패키지 버전·CHANGELOG와 함께 검사한다. 현재 배포는 x64 정적 라이브러리이며 같은 toolset·런타임 조건을 요구한다. RIONetLite/ 호환 계층에 관한 옛 제거 목표는 A03의 당시 결정 기록이며, 현재 제거를 약속하는 새로운 계약으로 읽지 않는다.

kQueued복사·수락이다. RIO 완료나 상대 ACK가 아니다.
kWouldBlocksend 링 공간 부족이다. 유계 retry/상위 rate limit/close를 선택한다.
kMessageTooLargeempty 또는 합계 크기 초과다. 입력을 수정한다.
kStaleSessionindex/generation이 현재 연결과 다르다. 이전 작업을 버린다.
kClosing서버나 세션이 종료 중이다. 새 작업을 만들지 않는다.
kUnavailable전송 게시 등 내부 실패다. 오류 로그와 close를 확인한다.
callback실행 위치·계약
OnConnected(SessionId)accept 스레드다. 다른 세션의 I/O callback과 동시 실행 가능하다. 같은 세션의 OnClosed가 반환 전에 추월하지 않는다. 예외는 격리·기록한다.
OnData(SessionId, span<const byte>) -> size_t해당 세션의 소유 I/O 워커다. 소비량은 0..span.size다. span 저장 금지다. 예외·초과 소비는 protocol close다.
OnClosed(SessionId, CloseReason)소유 I/O 워커다. 같은 수명에서 한 번이며 이후 OnData가 없다. 예외는 격리·기록한다.
Logger::IsEnabled(LogSeverity) const noexcept여러 호출 스레드에서 실행될 수 있다. 짧게 반환하고 예외를 던지지 않는다.
Logger::Log(LogSeverity,string_view) 및 Log(const LogEvent&)lifecycle/accept/I/O 등 동시 실행 가능하다. 저장하려면 string_view 내용을 복사한다. Log 예외는 격리한다. blocking file write는 별도 logging queue로 넘긴다.
adapter/decoder 함수계약
QueuedEventAdapter constructorsshard/events/payload/session 양수다. kDisconnect에는 CloseRequest가 필수다. invalid_argument 또는 allocation 예외가 가능하다. 명시적인 max_session_count는 서버와 맞춘다. 생략 overload는 shard×events를 session capacity로 사용한다.
adapter OnConnected/OnData/OnClosedEventHandler 구현이다. raw stream은 max_payload_bytes 이하 조각으로 복사·소비한다. 정책은 배압을 따른다.
TryPop(shard, destination, header) noexcept동시 producer/consumer 가능하며 짧은 shard mutex를 사용한다. kEvent면 destination이 owned copy다. kDestinationTooSmall은 제거 없이 필요한 크기를 header에 적는다. 잘못된 shard는 kEmpty다.
shard_count(), EstimatedMemoryBytes(), metrics()고정 설정/추정 또는 atomic snapshot이다. process 전체 메모리나 kernel pinned bytes를 뜻하지 않는다.
LengthPrefixedDecoder(max_packet_bytes)minimum header 크기 이상 maximum을 사용한다. 생성 자체는 noexcept다.
Decode(span, handler) -> DecodeResultimmutable decoder를 공유할 수 있지만 handler의 공유 상태는 사용자가 보호한다. span 전체에서 완성 packet만 callback한다. span 수명과 handler 예외는 호출자 책임이다. 자체 누적 없음, consumed_bytes/packet_count/error를 반환한다.
ToString(ErrorCategory/ErrorCode/SendResult/CloseReason) noexcept진단 문자열 변환이다.반환 string_view를 수정하지 않는다.

즉시 결과와 종료 원인

include/rionetlite/error.h

ErrorCategory는 실패 계층, ErrorCode는 공개 오류 종류를 나타낸다. Error에는 native code와 설정 field, message가 함께 들어 있다. code 문자열만 보고 OS 원인을 잃지 않는다.

SendResult는 동기 API의 즉시 수락 여부다. CloseReason은 나중 종료 통지의 원인이다. 이 둘을 하나의 bool로 줄이면 배압과 stale 연결, protocol 오류의 의미가 사라진다.

ToString은 enum을 로그나 UI에서 읽기 쉬운 이름으로 바꾸는 함수다. wire protocol type과 이 enum의 정수값을 같은 계약으로 쓰지 않는다. 내부 enum 순서가 네트워크 메시지 정의는 아니다.

  • src/error.cpp에서 모든 enum의 문자열을 비교한다.
  • ConvertLegacyError와 ConvertCloseReason을 찾는다.
  • Chat의 SendResult 처리 정책을 읽는다.
