02 / MENTAL MODEL

코드보다 먼저, 경계를 읽는다

누가 데이터를 소유하는가? 무엇을 완료로 간주하는가? 어떤 연결의 작업인가?

EchoServer는 공개 Server, EventHandler, LengthPrefixedDecoder로 구성된다. 애플리케이션은 소켓이나 completion queue를 직접 관리하지 않는다. 하지만 콜백 데이터의 유효 기간과 송신 결과의 의미는 알아야 한다.

경계실제 계약잘못 가정하면 생기는 일
콜백 → 애플리케이션OnData의 span은 콜백 반환 전까지만 유효하다.포인터만 큐에 넣으면 나중에 다른 데이터를 읽을 수 있다.
애플리케이션 → 송신Send는 반환 전에 데이터를 내부에 복사한다.애플리케이션 버퍼와 RIO 등록 버퍼의 수명을 혼동한다.
슬롯 → 연결SessionId는 index와 generation의 조합이다.오래된 작업이 새 연결에 적용될 수 있다.
kQueued는 어디까지의 성공인가?

송신 경로가 데이터를 받아들였다는 의미다. 상대 애플리케이션이 데이터를 처리했다는 확인은 아니다. 그런 확인이 필요하면 프로토콜에 응답이나 ACK를 설계해야 한다.

최소 Echo와 게임 서버의 차이

현재 Echo 예제는 콜백 안에서 디코딩하고 바로 Send를 호출한다. 패킷 하나의 경로를 보기 좋은 최소 예제다. 게임 로직이나 DB 작업을 추가할 때는 별도 큐와 워커로 넘기고, 데이터 수명과 이벤트 순서를 보존해야 한다. 8페이지에서 이 차이를 실험한다.

심화 · 복사 없는 API가 항상 좋은가?

복사를 줄이면 비용은 낮아질 수 있지만, 완료 전까지 호출자가 메모리를 유지해야 하는 계약이 생긴다. 현재 공개 API는 데이터를 복사해 호출자 버퍼의 수명과 내부 RIO 요청의 수명을 분리한다. 최적화할 때는 복사 비용뿐 아니라 이 계약을 바꾸는 복잡성도 함께 비교해야 한다.

05 / LIFETIME LAB
완료된 만큼만 앞으로 간다
버퍼의 수명은 함수 호출이 아니라 미완료 I/O와 연결되어 있다.
4바이트 rio!를 보냈지만 이번 완료에서 2바이트만 처리됐다고 가정한다. 처음 요청이 끝났다는 사실과 전체 데이터의 송신이 끝났다는 사실은 다르다. 현재 구현은 완료된 2바이트만 소비하고 남은 구간을 다시 게시한다.

완료 처리에서는 요청을 retire하고 미완료 카운트를 줄인다. 읽기 위치를 옮긴 뒤 아직 데이터가 있고 송신 접수를 허용하면 다음 요청을 준비한다. 이 실험은 완료 처리 함수 전체를 한 번에 실행하므로 부분 완료 후 카운트가 다시 1로 보인다.


해제 가능 판단의 범위를 구분한다
실험에서 미완료 요청 0은 이 송신 작업에 대한 조건만 확인한다. 실제 서버의 자원 해제에는 신규 게시 차단, 수신 I/O, 요청 큐와 워커의 수명까지 함께 확인해야 한다. 7페이지에서 종료 의존 관계를 살펴본다.

08 / BACKPRESSURE LAB
느린 게임 로직을 어디에 둘 것인가
작업을 큐로 옮기면 실행은 분리되지만, 처리 용량의 한계는 사라지지 않는다.
네트워크 콜백에서 DB나 긴 게임 로직을 실행하면 해당 워커의 다른 처리가 늦어진다. 공개 QueuedEventAdapter는 콜백을 shard별 유계 큐로 전달하며, 소비자는 TryPop으로 이벤트를 꺼낼 수 있다. 콜백 데이터의 수명과 연결·수신·종료 순서를 함께 다뤄야 한다.

큐가 찼을 때 무한 대기하면 네트워크 워커까지 느려질 수 있다. 용량과 포화 정책은 서비스 동작의 일부다. 실제 adapter에는 kRejectNewest와 kDisconnect가 있으며, 게임 프로토콜의 의미에 맞게 선택해야 한다. 데이터 손실을 허용하지 않는 메시지를 조용히 버리는 정책은 적절하지 않다.


심화 · 큐 크기를 늘리면 해결되는가?
일시적인 버스트를 흡수할 수는 있다. 그러나 평균 유입량이 처리량보다 계속 크면 큰 큐도 결국 포화된다. 큐 용량 확대는 메모리 사용량과 지연 증가를 동반한다. 처리 비용, 분산 방식, 유입 제한을 함께 검토해야 한다.

이 샘플의 근거와 재생성 방법
기준 커밋은 {{COMMIT}}이다. 소스 탐험기는 생성 당시 작업 트리의 12개 파일을 HTML 안에 포함하며 각 파일의 SHA-256을 표시한다. 이후 저장소가 변경되어도 이 HTML의 코드는 자동 갱신되지 않는다.
python docs/interactive_book/build_book.py
생성 스크립트는 코드 스냅샷을 갱신한다. 설명과 실험 모델의 의미까지 자동 검증하지는 않으므로, 구현 변경 후 본문 검토가 필요하다. 이 샘플에는 실제 실행 로그 재생과 임의 C++ 실행 기능은 포함하지 않았다.
